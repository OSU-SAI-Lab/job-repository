# Object Classification

Classifies object proposals against class-support embeddings using one or more embedding backends (OWLv2, BioCLIP, DINOv3). Each backend produces its own independent detection output file.

## How It Works

1. Loads **class-support embeddings** (`.npz`) generated by `class_supports/generate_class_supports_main.py`
2. Loads **proposal features** (`.npz`) generated by `proposal/generate_proposals.py`
3. For each backend, matches proposal features against class supports using:
   - **OWLv2** → `model.class_predictor()` (logit-based similarity)
   - **BioCLIP / DINOv3** → cosine similarity
4. Applies per-backend NMS and saves one detection JSON per backend

## Files

| File | Description |
|---|---|
| `object_classification_main.py` | CLI entry point |
| `object_classification_utils.py` | Backend detection logic (OWLv2 class predictor, cosine similarity, NMS) |
| `object_classification.def` | Apptainer/Singularity container definition |
| `requirements.txt` | Python dependencies |
| `run.sh` | Example run script |

## Usage

```bash
cd object_classification

python object_classification_main.py \
  --qry_path /path/to/images \
  --is_query_dir \
  --embedding_backends owlv2 bioclip dinov3 \
  --class_support_file_paths  cs_owlv2.npz  cs_bioclip.npz  cs_dinov3.npz \
  --object_features_file_paths of_owlv2.npz of_bioclip.npz of_dinov3.npz \
  --output_path /path/to/output
```

## Arguments

| Argument | Default | Description |
|---|---|---|
| `--qry_path` | *(required)* | Path to a single query image or a directory of images |
| `--is_query_dir` | `False` | Flag — treat `--qry_path` as a directory |
| `--output_path` | `None` | Root directory for output files |
| `--embedding_backends` | `owlv2` | One or more of: `owlv2`, `bioclip`, `dinov3` |
| `--class_support_file_paths` | — | Per-backend class-support `.npz` files, **aligned** with `--embedding_backends` |
| `--object_features_file_paths` | — | Per-backend proposal-feature `.npz` files, **aligned** with `--embedding_backends` |
| `--objectness_threshold` | `0.1` | Minimum proposal objectness score to consider |
| `--similarity_threshold` | `0.2` | Minimum class similarity score to accept a detection |
| `--nms_iou_threshold` | `0.5` | IoU threshold for per-backend NMS |
| `--model_name` | `google/owlv2-large-patch14-ensemble` | HuggingFace model ID (OWLv2 backend only) |
| `--device` | auto | `cuda` or `cpu` |

> ⚠️ `--class_support_file_paths` and `--object_features_file_paths` must have **the same number of entries** as `--embedding_backends`, in the same order.

## Outputs

Saved under `<output_path>/detections/`, one file per backend:

```
detections_owlv2_<sim>_<nms>_<prop_nms>_<timestamp>.json
detections_bioclip_<sim>_<nms>_<prop_nms>_<timestamp>.json
detections_dinov3_<sim>_<nms>_<prop_nms>_<timestamp>.json
```

Each JSON has the structure:
```json
{
  "annotations": [
    {
      "image_path": "/workdir/<filename>",
      "bounding_box": [x1, y1, x2, y2],
      "score": 0.87,
      "class": "species_name"
    }
  ]
}
```

## Pipeline Position

```
generate_class_supports_main.py   →  class-support .npz (per backend)
                                                          ↘
generate_proposals.py             →  proposal .npz       →  object_classification_main.py  →  detections .json
```
